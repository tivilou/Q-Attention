# Q-RMEA R73：递归恢复完整性与最小前缀恢复实现

本轮发布了ECQP递归checkpoint加载完整性修正和固定版本train-H前缀恢复模块。精确源码与单元测试生命周期经gpt-6.1-sol／medium单次独立静态审核，结论PASS_WITH_RISK，无必改项。源码补丁的隔离正向—回滚—再正向验证通过。共享CPU当前正运行其他项目任务，本轮尚未提交科学单元测试；没有真实数据恢复、训练或效果结果，L5未接受。

旧head只覆盖直接load_state_dict调用；PyTorch外层module的递归加载走_load_from_state_dict。新增递归检查要求checkpoint携带正确固定投影P，strict=False也拒绝缺失、符号替换、形状错误和非有限值。失败的包含模块须丢弃，未声称整个加载事务原子性。load_native仅复制核对后的共同参数，不替换B或P。此处行为预期由已冻结的CPU合成测试验证，不能把静态审核当作实测。

恢复模块保留R72的六个64MiB对象、固定VersionId和整片SHA界限，总有效载荷402653184B。它核验实际tar／NPY头、原始sidecar身份、prefix边界，并产生新前缀哈希；不宣称重算完整原始H哈希。已实现的真实run流程未开放给unit-only命令，六项原始恢复检查也不覆盖完整验收／删除生命周期。真实GET的费用准入和完整流程检查仍待完成。

当前单元契约仅允许合成unit：六项恢复检查、三项投影／共享梯度检查和十一项既有回归。worker部署是固定源码的干净独立目录；一次、不可自动重放、CPU一核、GPU零张卡。队列空闲及单例锁下复核是执行前提，任何等待超时都不表示其他任务结束，也不构成重放许可。此刻未生成绑定或提交记录。

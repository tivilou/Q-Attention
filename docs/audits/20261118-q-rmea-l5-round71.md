# Q-RMEA R71：ECQP 核心实现通过合成校验

本轮把R70探索草案实现为独立的experiments/rmea_ecqp模块，并通过共享调度器完成一项CPU合成测试。11项检查通过，实际计算约2.93秒，任务终止且原owner/worker绑定精确恢复。它仍是探索候选：没有真实数据前向、关联拟合、任务训练或新增效用结论，L5未接受。

主路线在原12个词态制备角度前加入固定投影的实体—词Hadamard交互，保留原8维电路、40个独立效果、EPS和signed读出。新增192个参数，共81220。token-square控制具有相同新增参数；token-linear验证可以折入原仿射层。softmax12与real-overlap12控制使用相同12维制备特征及40×12查询坐标、参数总量相同，但计算量、活跃容量和历史8维经典头均不相同。

实际测试中，零B时float32和float64的原生logits/attention/电路中间量均精确一致，正确与错配摘要也一致。最大梯度坐标的解析值0.00039924668386456797，中心差分0.0003992466801605587；一次合成SGD更新后，摘要错配引起prepare_raw最大变化约3.59e-7。这是计算路径与可训练性局部检查，不是任务收益或自然文本干预。其余检查覆盖固定P指纹、padding NaN/Inf隔离和零梯度、词序/样本次序、缺实体/坏mask/非有限值拒绝、六种控制前后向、线性折叠、全队列分组排除donor双射，以及直接状态恢复和损坏P拒绝。

gpt-6.1-sol/medium对冻结源码、测试、契约与调度生命周期给出PASS_WITH_RISK，无必改项。审核是静态审核，实际运行与输出hash由主模型另行验收。生命周期沿用既有单次、不可自动重放的CPU路径，并补上空闲检查竞态的控制器恢复分支；没有修改调度器运行时、容量或其他项目。进程崩溃/补偿失败仍可能需要人工恢复，未声称分布式事务崩溃原子性。

持久P只在构造和直接head加载时核验；未来被外层module递归加载时必须增加相应完整性门禁。当前均为直接head测试。实体上下文H已有标记信息，低秩双线性/实体感知先例明确，完整函数类分离、实质近邻区别和任务理论仍未成立，旧限定L4不迁移。

输入定位发现恢复缓存只有valid/test H，owner保留train元数据、roles/offsets/targets和原始train JSONL，但尚未找到train H或完整RoBERTa模型。没有拿valid/test替代训练输入，也没有访问它们的样本数组。下一步先为训练输入设计最小恢复：评估从已封存COS按固定分片恢复一个训练前缀的流量，和重建encoder特征比较成本；先冻结边界、实体分组fit/eval、donor映射、指标、灵敏度及不确定区间，再启动有界真实筛查。

源码已同步开发分支；原主分支、协作者分支、原源码和L4证据卡保持原范围。本轮零GPU、零COS请求/写入、零新增容量、零师弟服务器访问；正式完整实验继续由师弟执行。

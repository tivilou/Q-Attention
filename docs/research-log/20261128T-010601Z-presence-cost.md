# SEARCH-45 · 已测开销不足以解除 gen130 成本暂缓

本轮核实了一个具体原因：gen130 把逐微批持久化日志、CUDA 同步和额外健康检查都计入试跑的更新耗时，而科学运行器的日志和保存频率不同。**已单独复测的落盘开销不足以解释预算差距。** 不据此启动小筛，也不宣称科学运行器已经实测超预算。

## 用原始代码与原批次复算

- 核对 gen130 已归还的原终态及文件哈希，重算单卡 **4,001.25 GPU 秒**、两卡 **4,535.27 GPU 秒**。剩余 **3,048.543 GPU 秒、2,192.438 墙钟秒**。历史 551.457 GPU 秒，其中 gen130 实际 207.562 GPU 秒，继续保留。
- 每臂每个计时更新中，32 个输入微批各记一次进行中的持久日志，完整反向结束及即将执行优化器各记一次，因此计时圈内为 **34 次**。优化器完成的最后一次日志在计时圈外。科学核心在更新边界提交进度，检查点按改进、每32步或终态保存；两套 I/O 不应拿一个统一常数替换。
- 在原主机的同一文件系统，以过去四个日志前缀的长度构造人工内容，调用已核哈希的两份实际 I/O 函数。7 组交替执行，四臂总计时落盘相对每臂一次原子写入的差值中位 **0.209 秒**，实测 **0.187–0.290 秒**。没有 CUDA 或数据训练。该比较只覆盖 CPU 文件操作，不包含设备等待、GPU 重叠或科学检查点。
- 只用冻结 TRAIN 偏移量与批次索引重放原 micro4 的填充。首批 **7,228** 个填充后词位，640 训练批均值 **6,804.3**，p90 **7,204**、最高 **7,748**。选模32逻辑批均值 6,743.5，资格16批均值 6,802.25；没有取用任何标签或特征。把总训练时间全部按词位线性变化，是为了给隐含收益一个宽松的敏感性情形，而非模型计时。

## 投资决定

保持本精确实现的技术通过／成本暂缓，以及 gen98 10/13 原裁决。无需为调配卡顺序、换阈值或增加预算再付一轮测量成本。相位存在性构造仍有严谨的人工隔离证据，但没有公平科学小筛、全量确认或独立任务效用证据。

下一轮上移到**表达与执行结构的选择**，用同一误报／正类排序证据对照两个改变不同前提的方向：一是原候选预先写明单一等价表达，只在能减少主要操作且能严格匹配全值／对照的情况下保留；二是不继承原制备／读出执行瓶颈的独立量子构造，须提前给出公平 C/Gcov、去相干和既有预算内的可检验预测。对照高层选择完成前不再做另一次邻近成本诊断。任何重开需要适用的新证据和可审查的预算证明，不从人工 CPU 比例倒推出启动资格。

本轮只有既有 TRAIN 批次长度元数据和原位人工文件测试，0 新任务前向、训练或 GPU 分配。原限定 L4 及全部历史保留，L4‑T 目标仍处于 Active。

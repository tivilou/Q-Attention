# 条件查询：先排除等价变换，再检验 TRAIN 支持

我们希望解决“同一关系跨实体类型时，固定查询是否无法共同满足需求”的问题。先做完整 TRAIN 支持度统计，再决定是否值得检验查询冲突。统计请求仍排队，尚未获得数据结果或启动训练；不会挤占其他项目。

等待期间核清了一个理论边界：若所有关系使用同一个条件酉变换，旋转 query 与反向旋转 key 在状态端完全等价。实际 EPS、mask、归一化和有符号读出下，数值误差分别不超过 4.45e-16、2.23e-16 和 3.11e-15。因此，单纯把旋转移到 query 端不能算新的量子机制。

另一个容易误判的地方是去相干基：折叠酉变换却固定原去相干基，fixture 分数可差约 0.182；把通道基一起变换后误差为 2.78e-16。前一个差值不是新的任务收益或量子创新证据。

以上是已知代数恒等式的小型验证，不是新定理、自然文本结果或浅线路函数族相同的证明。此前五路完整预算负结果及新 L3/L4-T 未验收的结论不变。

下一步仍按原预声明统计所有 TRAIN 行：至少三个正关系各自具有两种不少于一百个独立句子的类型组合，才进入新的冻结查询冲突诊断；支持通过也不等于机制成立。没有 TEST 调参、额外种子、模型训练或新增 COS 写入。

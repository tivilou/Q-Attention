# 问题优先：类型兼容修复之后，真实关系仍被漏掉

[已测事实] 找到一项能直接改善预测的任务问题：模型没有显式使用给定实体类型，因而会预测与类型不兼容的关系。固定 TRAIN 类型规则对历史完整训练的五种关系头均提高了开发验证集 Macro-F1。它是通用修复，不是量子创新。更值得继续研究的问题是：**实体类型允许正确关系时，模型为什么仍把真实关系判成无关系？**

## 实际工作流与这次改动

本项目输入句子及已标注的主、客体位置，冻结 RoBERTa-large 编码每个词，再由关系头对上下文加权、聚合并输出40类关系分数，其中一类为无关系。原编码输入使用不带实体类型的标记。历史五种关系头在同一58,465条 TRAIN 上完成20轮训练，各自按开发 VALID 选择既定检查点。本次不改变这些选择、不训练新历史模型，也不评估 TEST。

本次分两条线。轻量线把主语、宾语、其余上下文分别均值池化，拟合经典线性分类器；另一条线直接复用历史 uniform、relation_softmax、real_overlap、quantum、dephased 五个最终选择模型，在相同重建缓存上做一次推理。两条线都考察给定实体类型的作用，训练预算不同，分开报告。

主诊断指标为39个正关系类别的宏平均 F1（Macro-F1）；同时记录修正/破坏的预测数、把真实关系判成无关系的漏检，以及把无关系误判成正关系的误报。该39类指标不能替换历史协议的40类主指标，原历史报告保持原样。

| 上一检查点 | 本次新增 | 用途 |
| --- | --- | --- |
| 固定原生检查点的类型规则有效，偏置校准失败 | 不输入原生 logits 的经典池化分类器 | 检查简单实体/上下文特征是否足够 |
| 尚缺同类型输入的完整经典头比较 | 五个已完成历史模型全部施加相同规则 | 区分通用任务改进和量子独有效果 |

## 固定设置与结果

类型规则只由已固定的4,192条 TRAIN 建立；保留无关系、未见类型对的全部类别、拟合中缺失的类别23。规则 SHA-256 为 `d4c1100df6d306a3fae48d66f7907dfbe2a39d1b30843abb359ba32de7053186`。评估全19,584条重复使用过的开发 VALID。类型属于新增明确输入，所有对照同等使用；没有读取 VALID 标签来构建规则。

轻量经典线：4,192条拟合，4,000条 TRAIN 评估；特征3072维，类型版再加25维类型对。拟合内中心化/分块能量归一化；固定均值交叉熵加 `0.5*(1/4192)*||参数||²`，零初始化，一次拟合，不调参。所有40列保留。两臂梯度无穷范数均小于1e-6。

## 已定位的问题与尚待解释的成因

[已测事实] 固定类型规则是有效但不完整的修复。它还排除了130条 VALID 的真实标签，属于有限 TRAIN 支持缺失，不是逻辑上不可能的关系。经典 softmax 的漏检还由1843增到1976：删除竞争关系可能使无关系成为首选，不能只展示收益而隐去这项代价。

[已测事实] 在四个非均匀完整模型共同使用类型规则后：

- 四者共同漏检1,155条真实关系；其中**1,070条的真实关系仍被类型规则允许**，不是硬类型删除导致。
- 经典 softmax 漏检的1,976条中，737条至少被另一个既有模型正确识别；这是已有预测中可观察到的修复空间，不是部署算法或新模型增益。
- Q-RMEA 相对经典 softmax 修复984条、破坏1047条，净少正确63条。它修复458条经典漏检，同时在经典原本正确的样本上新增566条漏检。存在互补信号，但直接换头不足以带来净收益。
- 共同漏检分布覆盖多种关系，例如任职关系150条、组织国家76条、身份关系76条、组织成员73条。完整39类结果均保留；这些例子不是预选子集效果或显著性证据。

[机制解释] 下一步应研究“如何利用句子证据确认实体之间确有关系，同时保住无关系样本的判别”。只凭错误计数，还不能把它归因于注意力分散、实体绑定、词特征缺失或量子相干性。

[尚未证明] 1,070条共同漏检中有多少是句子明确支持的可学习关系、多少涉及跨句指代或标签歧义，尚未完成语义核查；737条可被其他模型修正，也不意味着存在无需标签的正确选择器。此处没有给出 oracle 分数或把潜在空间写成实际收益。

## 证据、案例与决定

轻量线经 A6API `gpt-6.2-astra` high 一次机制审核 PASS，随后实际拟合及四张混淆矩阵复算通过。历史线复用既定模型、既定规则及原执行包装器，为 R0 只读测量；十张混淆矩阵、计数和 Macro 独立复算一致。两项分配均已归还，进程退出。没有改稳定训练核心或重复做续训/COS测试矩阵。

本次保存拟合收敛、最终logits和汇总，不生成新的 `sample-trace.v2` token级机制案例；缺少逐词权重/反馈链，因此不宣称已解释漏检成因或案例材料完备。训练过程案例不适用于历史推理线；原历史轨迹不迁移、不补造。原始文本、检查点和逐样本数组保持私有，不进入GitHub，也没有下载新的数据/模型到Windows。既有检查点只做RAM转发。廉价可重建线性系数和回放输出不新增COS副本。

本轮证据上限：重复开发集上的问题发现及固定规则修复；不是新独立实证、量子优势或L5。原限定L4保留，L5仍未验收。

**唯一推荐下一步：先区分“关系证据未被利用”和“当前输入根本不足”。** 在TRAIN上以输入哈希固定样本，结合已有完整模型和相同类型输入，对真实关系漏检/正确识别及无关系误报/正确拒绝做配对语义检查；确定可观测的上下文结构后，才提出对应量子操作及同输入经典对照。最低检查为固定且互斥的四类各8条、不训练、不访问TEST；核查标准是句中是否明确支持目标关系、指代是否充分、是否有竞争实体/证据跨度，保留不确定和反例。成功条件是在明确支持且类型合法的漏检中找到有对照的重复结构；若只是标签歧义或输入缺失，则关闭对应结构解释，不凭调阈值复活已失败偏置配置。预计CPU小于1分钟、GPU训练0；既有授权足够。当前仅提出该下一步，尚未执行。

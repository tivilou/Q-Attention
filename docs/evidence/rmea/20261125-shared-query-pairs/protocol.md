# Shared-query pair feasibility: one fixed-model TRAIN diagnostic

Question: does some individually reachable error require a query incompatible with a fixed correctly classified same-label example? The earlier full TRAIN Rayleigh study allowed a different query for every input AND moved competing rows to their minima. It found3579/3611 Q errors reachable under that broad relaxation, not that one shared query can repair them. Existing gradient-transfer, finite-step and rank2 fits answer different questions. This diagnostic changes no model/measurement rank, trains nothing and cannot promote those closed profiles.

No new VALID/TEST, encoder, optimizer, checkpoint, COS or Windows task arrays. Native real12 uses normalized12-dimensional real keys/query; Q uses the original3qubit prepared states. Replay all rows once because current gold/rival margins and the complete common pairing population are required, not as baseline retraining.

For example i with gold r, fixed token keys k_it, original signed utility u_irt and EPS1e-6, define

    B_i = sum_valid k_it k_it^dagger + EPS*T_i*I
    A_ir = sum_valid u_irt k_it k_it^dagger + EPS*sum_valid u_irt*I
    c_i = max_{s!=r} native_logit_is - native_bias_r
    C_i = A_ir-c_i B_i.

B_i is strictly positive. A free unit query makes this gold row strictly beat ALL fixed native rivals exactly when q^dagger C_i q>0. Positive scaling of C does not change this condition; use C/||C||_F, with zero matrices left zero. Any infeasibility claim concerns these frozen computed matrices/numerical tolerances, not an interval certificate for ideal arithmetic or the whole learned model.

Row indices are exact cache indices, not assertions of sentence uniqueness.

For each pair/model, write D=C_i/||C_i||_F, F=C_j/||C_j||_F. For every density E>=0,Tr(E)=1,

    min(Tr(ED),Tr(EF)) <= lambda_max(lambda*D+(1-lambda)*F), 0<=lambda<=1.

A negative right side at ANY valid lambda rules out satisfying both, even over mixed effects and hence every native pure-query circuit. Separately require lambda_max(D)>1e-7 AND lambda_max(F)>1e-7 before calling it a shared-query conflict; otherwise classify individual-obstruction or unresolved instead.

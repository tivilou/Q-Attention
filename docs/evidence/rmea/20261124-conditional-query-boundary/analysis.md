# TRAIN 不支持本轮“关系内跨类型条件查询”问题

研究流程：先冻结支持度门槛，再扫描完整 TRAIN 的关系标签、主客体类型和句子身份，最后决定是否进入查询冲突诊断。没有调用模型、更新参数或读取 VALID/TEST。

预声明要求至少三个正关系，每个关系有两种类型组合，且每种组合至少一百个独立句子。全部 58,465 条 TRAIN、40 类均计入，句子按完整 token 序列的 SHA256 去重；源文件哈希保持 f1051d574a44df3ecbd036c1de4fbbe0a372c768f6ec990330e2cea4a657269f。

| 结果 | 数值 |
| --- | --- |
| 满足条件的正关系 | 仅 per:employee_of，一个 |
| PERSON→ORGANIZATION | 1,689 行，1,461 个独立句子 |
| PERSON→COUNTRY | 304 行，296 个独立句子 |
| 达到三个正关系门槛 | 否 |

因此关闭这个固定类型异质性方向，不降低支持阈值、只挑 employee_of、改采样或直接训练条件查询插件。此结果不否定所有条件量子测量，也不证明同一关系一定只需单一查询；它只说明本轮问题没有通过事先约定的数据支持条件。

统计还显示 no_relation 有 38,761 行（占全部 TRAIN 约 66.30%）、25 种类型组合，其中 21 种达到一百个独立句子。这个完整统计是描述性事实，不是新的通过门槛或因果瓶颈。Q-RMEA 的 effect 选择 token，类别分数还经过有符号 value/decoder；不能仅凭负类异质性便推导出“无关系纯态原型不够”或“混态一定更优”。

原先给这项元数据计数申请计算配额过重。最终通过现有控制节点做短时只读文件扫描，耗时 1.435 秒，进程 peak RSS 约 21.5 MiB，没有写远端文件，也没有访问其他项目占用的计算节点。保留原科学门槛，已撤销尚未交付/分配的过时请求。没有启动 GPU 作业或修改调度器实现。

此前五路全量负结果及新 L3/L4-T 未验收保持不变。下一步先核对 no_relation 相关原始研究和既有失败方案，再利用当前完整模型的 TRAIN 对照错误结构选择问题；不从类别频次直接跳到插件。

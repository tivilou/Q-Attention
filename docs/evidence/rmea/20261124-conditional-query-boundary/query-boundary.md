# 条件查询的等价边界与待检验问题

当前五路完整预算结论未改变：同一冻结缓存上，Q 的测试 Macro 低于去相干和两个公平经典头，故新 L3/L4-T 未验收。TRAIN 类型支持度统计尚在排队，没有结果，也没有启动新训练。

新候选问题是：同一关系跨实体类型组合时，固定关系查询是否产生不可共同满足的任务需求？支持度统计只检验这种问题是否有足够数据，不能证明查询冲突。原 token 编码已经含实体标记，不能把它当作不知实体类型的编码器；须区别额外输入、容量和量子机制。

## 一个应提前排除的论证

若所有关系的条件查询是同一个输入条件酉变换 `q_r(t)=U_t q_r`，则

`|<U_t q_r, k_j(t)>|² = |<q_r, U_t† k_j(t)>|²`。

这在状态端是精确等价。保持实际实现的 mask、EPS=1e-6、按 token 归一化以及有符号 value/decoder 不变，attention 和最终 logits 均相同。因此，“把同一个条件旋转放到 query 端”本身没有建立新的状态端功能，也不构成理论创新。这是已知酉内积恒等式，本记录不申请新定理或新颖性。

实际 Q-RMEA 的 key/query 由固定两层 RY/RZ/CNOT 浅线路生成。该 ansatz 不保证在任意 U_t† 下闭合，所以也不能反向宣称已证明现有参数化模型具有相同可训练函数族。增加线路深度、输入或参数导致的差别需要分别对照，不能用状态端恒等式直接判断任务上无用。

若条件变换还依赖关系，即 U_(r,t)，通常不能折叠为所有关系共享的一个 token 编码。这个区别尚不证明量子优势；经典条件查询须得到相同输入和适当参数/训练预算，且必须排除已测试类型偏置/类别硬筛的等价解释。

## 去相干对照的基必须跟踪

普通去相干分数为 `Tr(P_r D(K_j))`。把条件酉变换从 query 移到 key 后，匹配的通道应为

`D_U(X)=U† D(U X U†) U`，

而不能无说明地保留原坐标中的 D。后者通常改变对照函数；相干分数保持相同不代表去相干分数也保持相同。这个差别本身不是新的量子贡献证据。

query_boundary.py 用 40 个查询、11 个 token、8 维状态和实际 EPS/mask/有符号读出检验以上等价，另验证跟踪通道基后的去相干一致性。它是微型代数 fixture，不是原 checkpoint 回放、自然文本证据、性能实验或独立外审。

后续仍先完成原预声明的 TRAIN 支持度统计；统计若通过，只能进入另行预声明的冻结查询冲突诊断。不得用类型频次、上述恒等式或单独相干/去相干差值跳过独立贡献验证。
